# Графовый планировщик последовательности интенций поверх FB-представлений
---

## 1. Аннотация

В работе исследуется проблема долгосрочного планирования в иерархическом zero-shot RL на основе Forward-Backward представлений. Обученный high-level контроллер выбирает одну латентную интенцию за раз, что ограничивает его способность решать задачи с длинными последовательностями препятствий.

В рамках исследования предлагается графовый планировщик, который:
- строит граф состояний из offline-датасета, используя $B$-эмбеддинги как координаты вершин;
- находит путь от текущего состояния к цели алгоритмом Дейкстры;
- исполняет последовательность подцелей через имеющуюся low-level политику.

Метод не требует обучения, генеративных моделей мира или взаимодействия со средой. Эксперименты на `antmaze-medium-navigate-v0` показывают, что метод принципиально работоспособен (на некоторых задачах до 60% success rate без какого-либо дообучения), но уступает обученному high-level контроллеру.

---

## 2. Графовый планировщик

### 2.1 Ключевая идея

Представим offline-датасет как граф достижимости. Каждое состояние — вершина; рёбра соединяют состояния, близкие в пространстве $B$-эмбеддингов. Путь от старта к цели находится алгоритмом Дейкстры, а промежуточные вершины становятся последовательностью подцелей для $\pi_\ell$.

```
Старт ──>    w₁    ──>    w₂    ──>    w₃    ──>   ...   ──> Цель
            │             │            │
            πℓ(·|s,z₁)    πℓ(·|s,z₂)   πℓ(·|s,z₃)
            25 шагов      25 шагов     25 шагов
```

### 2.2 Вычисление B-эмбеддингов

Для каждого состояния $s_i$ из подвыборки датасета вычисляем:

$$\mathbf{b}_i = B(s_i) \in \mathbb{R}^d$$

Эмбеддинги нормализуются на сферу радиуса $\sqrt{d}$:

$$\hat{\mathbf{b}}_i = \frac{B(s_i)}{\|B(s_i)\|_2}\sqrt{d}$$

$B$-пространство кодирует структуру посещаемости. Состояния, достижимые одним и тем же поведением, имеют близкие по направлению $B$-эмбеддинги.

### 2.3 Построение k-NN графа

Вершины: $V = \{s_1, \ldots, s_N\}$, где $N = |\mathcal{D}| / \text{stride}$.

Рёбра: для каждой вершины находим $k$ ближайших соседей по косинусному расстоянию:

$$d_{\cos}(s_i, s_j) = 1 - \frac{\mathbf{b}_i \cdot \mathbf{b}_j}{\|\mathbf{b}_i\| \cdot \|\mathbf{b}_j\|}$$

Веса рёбер:

$$w(s_i, s_j) = 1 - \frac{d_{\cos}(s_i, s_j)}{2} \in [0, 1]$$

Граф хранится как разреженная матрица смежности $G \in \mathbb{R}^{N \times N}$ формата CSR.

$B$-эмбеддинги лежат на сфере, поэтому косинус информативнее евклидова расстояния. Косинусная близость отражает временну́ю близость состояний — насколько они посещаются одним и тем же поведением.

### 2.4 Определение целевой вершины

Целевой латент $z_r$ не обязательно совпадает с $B(s)$ для какого-то конкретного состояния. Находим ближайшую вершину по косинусному сходству:

$$s_{\text{goal}} = \arg\max_{s_i \in V} \frac{\mathbf{b}_i \cdot z_r}{\|\mathbf{b}_i\| \cdot \|z_r\|}$$

### 2.5 Поиск пути (алгоритм Дейкстры)

Для текущего состояния агента $s_{\text{curr}}$:
1. Находим ближайшую вершину $s_{\text{start}}$ через $B(s_{\text{curr}})$.
2. Запускаем алгоритм Дейкстры от $s_{\text{start}}$ до $s_{\text{goal}}$.
3. Получаем путь $P = (s_{\text{start}}, v_1, v_2, \ldots, s_{\text{goal}})$.

Алгоритм Дейкстры минимизирует сумму весов рёбер, что эквивалентно максимизации косинусной близости последовательных состояний — т.е. нахождению наиболее «плавного» маршрута в $B$-пространстве.

Если путь не найден (вершины в разных компонентах связности), возвращается прямой переход $[s_{\text{start}}, s_{\text{goal}}]$.

### 2.6 Исполнение последовательности подцелей

На шаге $t$ эпизода активная подцель определяется как:

$$j(t) = \min\left(\left\lfloor \frac{t}{H} \right\rfloor,\; K - 1\right), \qquad z_{\text{sub}}(t) = \hat{\mathbf{b}}_{v_{j(t)}}$$

где $H$ — число шагов на подцель. Действие выбирается предобученной политикой:

$$a_t \sim \pi_\ell(\cdot \mid s_t, z_{\text{sub}}(t))$$

Каждые $R$ шагов план перестраивается от текущей позиции (коррекция отклонений).

## 3. Реализация

### 3.1 Структура кода

```
├── graph_planner.py
│   ├── FBGraphBuilder        # вычисление эмбеддингов + построение графа
│   │   ├── _compute_embeddings()   # B(s) для всех состояний (батчами)
│   │   ├── build_graph()           # k-NN граф, разреженная матрица
│   │   ├── find_nearest_node()     # привязка состояния к вершине
│   │   └── find_path()             # Дейкстра + восстановление пути
│   ├── GraphPlanner           # логика планирования
│   │   ├── plan()                  # построение последовательности подцелей
│   │   └── get_current_intention() # выдача текущей подцели + переключение
│   └── GraphPlannerAgent      # обёртка поверх агента
│       └── sample_actions()        # замена high_actor на планировщик
├── evaluate_graph_planner.py  # скрипт оценки метода
└── evaluate_baseline.py       # скрипт оценки бейзлайна
```

### 3.2 Ключевые гиперпараметры

| Параметр | Значение | Описание |
|---|---|---|
| `k_neighbors` | 10 | Число соседей в k-NN |
| `graph_metric` | cosine | Метрика близости |
| `subsample_stride` | 5 | Берется каждая 5-ая вершина из $B$ для ускорения |
| `steps_per_subgoal` | 25 | Число шагов между подцелями |
| `max_subgoals` | 8 | Ограничение длины плана |
| `replan_interval` | 200 | Коррекция отклонений |

## 5. Анализ

### 5.1 Основные недостатки по сравнению с предоставленным high-level контроллером.

- Отсутствие адаптивности. Обученный $\pi_h$ выбирает подцель на каждом шаге, учитывая текущее состояние. Граф строится раз в 200 шагов и не реагирует на локальные отклонения.

- 25 шагов на подцель не учитывают реальное расстояние: близкая подцель тратит лишние шаги, далёкая — не достигается.

- Косинусная близость в $B$-пространстве не гарантирует физической достижимости: два состояния могут быть близки по $B$, но разделены стеной.

- Использование каждого 5-го состояния снижает плотность графа. Как видно, успешность задач повышается при выборке из всех возможных состояний графа. Приходится балансировать между временем работы и качеством.

### 5.2 Сравнительный анализ подходов

| | Бейзлайн $\pi_h$ | Графовый планировщик |
|---|---|---|
| Горизонт рассуждения | 1 подцель | $K$ подцелей |
| Адаптивность | Каждый шаг | Каждые 200 шагов |
| Требует обучения | Да | Нет |
| Вычислительная стоимость | 1 проход сети | Дейкстра + k-NN |

## 6. Ограничения и будущая работа

| Проблема | Потенциальное решение |
|---|---|
| Фиксированные 25 шагов на подцель | Адаптивное переключение по падению $F(s, z)^\top z$ |
| Рёбра, пересекающие стены | Использование $F$ для взвешивания рёбер графа |
| Одна цепочка подцелей | Поиск по множеству кандидатных маршрутов |

Также хочется отметить, что текущий объем тестирования не позволяет сделать однозначные выводы, а лишь предварительно дает понимание недостатков и дальнейших улучшений метода. Необходимо провести полноценное исследование с анализом результатов при изменении значений различных гиперпараметров, а также внести теоретические улучшения в сам метод.
